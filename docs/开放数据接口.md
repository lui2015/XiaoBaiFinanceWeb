# 小白财经开放平台接口文档（v1）

面向第三方系统 / AI 的**数据读取与投稿**接口。所有接口都带站点前缀 `/XiaoBaiFinance`（Next.js `basePath`），调用时不要漏掉。

> 在线文档（公开只读，可直接分享或交给 AI 阅读）：
> `GET https://www.luliming.xyz/XiaoBaiFinance/api/open/docs?doc=data`
>
> 能力索引（公开只读，返回全部端点清单）：
> `GET https://www.luliming.xyz/XiaoBaiFinance/api/open/v1`
>
> 旧版投稿文档：`GET .../api/open/docs`（默认返回，仅描述投稿接口）

---

## 1. 快速开始

```bash
BASE="https://www.luliming.xyz/XiaoBaiFinance"
KEY="xb_open_你的密钥"

# 分类树
curl -s "$BASE/api/open/v1/categories" \
  -H "Authorization: Bearer $KEY"

# 文章列表：第 1 页，每页 10 条
curl -s "$BASE/api/open/v1/articles?page=1&size=10" \
  -H "Authorization: Bearer $KEY"

# 文章详情
curl -s "$BASE/api/open/v1/articles/123" \
  -H "Authorization: Bearer $KEY"
```

## 2. 鉴权

### 2.1 获取 API Key

三类密钥**任一有效**即可调用开放接口：

| 来源 | 前缀 | 获取方式 | 调用统计计入 |
|---|---|---|---|
| 管理端文件密钥 | `xb_open_` | 登录后进入「内容管理 → 开放平台」→「+ 生成新 Key」→ 立即复制保存 | 开放平台页的「当日 / 累计调用次数」 |
| 用户数据库密钥 | `xbk_live_` | 「设置 → 开放平台」→「创建新密钥」，明文仅展示一次，库中只存 sha256 | 设置页的「今日 / 累积调用次数」 |
| 运维环境变量 | 自定义 | `OPEN_API_KEY`（单值）或 `OPEN_API_KEYS`（逗号分隔多个） | 开放平台页的「当日 / 累计调用次数」 |

> 明文密钥只保存在你的服务端配置中，请勿提交到代码仓库、写入 URL 或打印到日志。
> `xbk_live_` 密钥依赖 `open_api_key` 表（migration `20260723_add_open_platform`），部署时由 `prisma migrate deploy` 自动创建；文件式与环境变量密钥不依赖该表。

### 2.2 携带方式

二选一，**推荐第一种**：

```http
Authorization: Bearer <API_KEY>
X-API-Key: <API_KEY>
```

- 数据读取接口 `/api/open/v1/*` **只接受请求头**，不支持 `?key=`。
- 旧投稿接口 `POST /api/open/articles` 为兼容历史调用保留 `?key=<API_KEY>`，但密钥会进入访问日志，**不建议使用**。
- 索引 `/api/open/v1` 与文档 `/api/open/docs` 无需鉴权。

### 2.3 安全须知

- 本接口面向**服务端到服务端**调用，未配置 CORS 响应头；浏览器前端直连会被同源策略拦截，也会导致密钥泄露。请由你的后端代理调用。
- 密钥按 SHA-256 摘要做时序安全比对；服务端不保存数据库密钥明文。
- 限流以密钥摘要为维度，不依赖可伪造的 `X-Forwarded-For`。
- 密钥泄露后请立即在对应页面删除 / 吊销并重新生成。

## 3. 通用约定

### 3.1 响应格式

数据读取接口统一返回（与站内接口一致）：

```json
{ "code": 0, "message": "ok", "data": { }, "traceId": "m1x2ab3c" }
```

失败时：

```json
{ "code": 1002, "message": "API Key 无效", "data": null, "traceId": "m1x2ab3c" }
```

| code | HTTP | 含义 |
|---|---|---|
| `0` | 200 | 成功 |
| `1001` | 400 | 请求参数错误 |
| `1002` | 401 | 缺少 / 无效 / 已停用的 API Key |
| `1004` | 404 | 文章不存在或未发布 |
| `1007` | 429 | 触发限流 |
| `1500` | 500 | 服务器内部错误 |
| `2001` | 400 | 参数校验失败，`data` 中给出字段级错误明细 |

> `POST /api/open/articles`（投稿）为兼容历史调用方，响应的 `code` 直接等于 HTTP 状态码（成功为 `0`，失败为 `400/401/403/429/500`），且不含 `traceId`。判断成功请统一以 `code === 0` 为准。

### 3.2 数据范围与时间

- 只返回 `status = 1`（已发布）且未删除的文章，草稿、下架、软删除内容不会泄露。
- 返回字段为白名单，不包含 `createdBy`、`authorAdminId`、`deletedAt` 等内部字段。
- 时间字段为 **UTC ISO 8601** 字符串，例如 `2026-08-16T15:17:05.057Z`；北京时间 = UTC + 8 小时，即 `2026-08-16 23:17`。前端展示请用 `toLocaleString('zh-CN', { timeZone: 'Asia/Shanghai' })`。

### 3.3 分页与限流

| 项 | 约定 |
|---|---|
| `page` | 从 1 开始，最大 10000 |
| `size` | 默认 20，最大 50 |
| 数据读取限流 | 每密钥每分钟 120 次 |
| 投稿限流 | 每密钥每分钟 60 次（独立计数） |
| 统计 | 每次**成功**调用计入对应页面；鉴权失败、参数错误、限流不计 |

> 限流为进程内计数、多实例不共享，服务重启后清零；后续可接入 Redis 做全局限流。

## 4. 接口清单

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| GET | `/api/open/v1` | 否 | 能力索引 |
| GET | `/api/open/docs?doc=data` | 否 | 本文档（Markdown 纯文本） |
| GET | `/api/open/v1/articles` | 是 | 文章列表（分页 / 筛选 / 搜索 / 排序） |
| GET | `/api/open/v1/articles/{idOrSlug}` | 是 | 文章详情（含正文、标签） |
| GET | `/api/open/v1/categories` | 是 | 分类树 |
| POST | `/api/open/articles` | 是 | 投稿发布文章 |
| GET | `/api/open/articles` | 否 | 投稿接口字段自述 |

### 4.1 GET /api/open/v1/articles —— 文章列表

请求参数（均为 query）：

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `page` | int | 否 | 页码，默认 1 |
| `size` | int | 否 | 每页条数，默认 20，最大 50 |
| `categoryId` | 数字字符串 | 否 | 一级分类 ID |
| `subCategoryId` | 数字字符串 | 否 | 二级分类 ID |
| `categorySlug` | string | 否 | 一级分类 slug（小写字母/数字/连字符），与 `categoryId` 可二选一 |
| `q` | string | 否 | 关键词，匹配标题与摘要，最长 50 字 |
| `sort` | `latest` \| `hot` | 否 | 默认 `latest`（按发布时间倒序）；`hot` 按浏览量倒序 |
| `recommend` | `0` \| `1` | 否 | 传 `1` 只返回推荐文章 |

> 中文关键词需做 URL 编码（例如 `q=%E5%9F%BA%E9%87%91`），否则部分 HTTP 客户端会发送非法 URL；`fetch` / `requests` 等库会自动编码。

响应示例：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "list": [
      {
        "id": 80,
        "title": "什么是基金定投",
        "slug": "what-is-fund-dca",
        "summary": "基金定投是……",
        "coverUrl": null,
        "sourceType": 0,
        "categoryId": 1,
        "subCategoryId": 2,
        "viewCount": 128,
        "likeCount": 6,
        "favoriteCount": 3,
        "isRecommend": false,
        "publishAt": "2026-08-16T15:17:05.057Z",
        "updatedAt": "2026-08-16T15:17:05.057Z",
        "category": { "id": 1, "name": "基础概念", "slug": "basics" },
        "subCategory": { "id": 2, "name": "名词解释", "slug": "glossary" }
      }
    ],
    "total": 236,
    "page": 1,
    "size": 20,
    "hasMore": true
  },
  "traceId": "m1x2ab3c"
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `list[].id` | int | 文章 ID，可直接用于详情接口 |
| `list[].slug` | string | URL 友好标识，可直接用于详情接口 |
| `list[].sourceType` | int | 0 = HTML，1 = Markdown，2 = 在线 |
| `list[].publishAt` / `updatedAt` | string \| null | UTC ISO 8601 |
| `list[].category` / `subCategory` | object \| null | 分类 ID、名称、slug |
| `total` | int | 符合条件的文章总数 |
| `hasMore` | boolean | 是否还有下一页 |

> 列表**不返回正文**，避免响应过大；需要正文请调详情接口。

### 4.2 GET /api/open/v1/articles/{idOrSlug} —— 文章详情

`idOrSlug` 可传数字 `id` 或 `slug`，只允许字母、数字、中文、`_`、`-`，长度 1–80。

```bash
curl -s "$BASE/api/open/v1/articles/what-is-fund-dca" \
  -H "Authorization: Bearer $KEY"
```

响应 `data` 结构：

```json
{
  "article": {
    "id": 80,
    "title": "什么是基金定投",
    "slug": "what-is-fund-dca",
    "summary": "基金定投是……",
    "contentHtml": "<p>已净化的正文 HTML</p>",
    "contentText": "已净化的正文 HTML",
    "contentMd": null,
    "tags": [{ "id": 1, "name": "基金", "slug": "fund" }],
    "category": { "id": 1, "name": "基础概念", "slug": "basics" },
    "publishAt": "2026-08-16T15:17:05.057Z"
  },
  "url": "/XiaoBaiFinance/article/what-is-fund-dca"
}
```

| 字段 | 说明 |
|---|---|
| `contentHtml` | 入库时已做白名单净化（移除 `<script>`、`on*` 事件、`javascript:` 等）的 HTML |
| `contentText` | 去标签纯文本，适合做摘要 / 全文检索 / 喂给模型 |
| `contentMd` | Markdown 原文，仅 Markdown 投稿的文章有值 |
| `tags` | 标签数组 |
| `url` | 站内文章页相对路径，拼接域名即可访问 |

> 该接口**不增加**站内浏览量 `viewCount`，重复拉取不会污染热度统计。
> 即使服务端已净化，第三方渲染 `contentHtml` 时仍应自行做 HTML 白名单过滤或转义，不要直接 `innerHTML` 拼接不可信内容。

### 4.3 GET /api/open/v1/categories —— 分类树

返回启用中的分类，按 `sortOrder` 排序，子分类嵌套在 `children` 中；一级分类的 `id` / `slug` 可直接用于列表筛选与投稿。

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "total": 16,
    "list": [
      {
        "id": 1,
        "name": "基础概念",
        "slug": "basics",
        "parentId": null,
        "iconUrl": null,
        "description": "……",
        "sortOrder": 1,
        "children": [
          { "id": 2, "name": "名词解释", "slug": "glossary", "parentId": 1, "children": [] }
        ]
      }
    ]
  },
  "traceId": "m1x2ab3c"
}
```

### 4.4 POST /api/open/articles —— 投稿发布

```bash
curl -X POST "$BASE/api/open/articles" \
  -H "Authorization: Bearer $KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "title": "一篇投稿文章",
    "summary": "摘要（可省略，自动截取正文）",
    "categoryId": "1",
    "subCategoryId": "2",
    "status": 1,
    "sourceType": 0,
    "contentHtml": "<h2>小标题</h2><p>正文内容……</p>"
  }'
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `title` | string(2–60) | 是 | 标题，slug 由服务端自动生成并保证唯一 |
| `categoryId` | 数字字符串 | 是 | 一级分类 ID，请先调分类树接口获取 |
| `contentHtml` | string | `sourceType=0` 时必填 | HTML 正文，服务端净化后入库 |
| `contentMd` | string | `sourceType=1` 时必填 | Markdown 正文 |
| `summary` | string(≤120) | 否 | 缺省自动截取正文前 120 字 |
| `subCategoryId` | 数字字符串 | 否 | 二级分类 ID |
| `coverUrl` | string(url) | 否 | 封面图 URL（仅存储，服务端不抓取，无 SSRF 风险） |
| `status` | `0` \| `1` | 否 | 0 = 草稿，1 = 直接发布（默认 1） |
| `sourceType` | `0` \| `1` | 否 | 0 = HTML（默认），1 = Markdown |

成功响应：

```json
{ "code": 0, "data": { "id": "123", "slug": "my-post" }, "message": "ok" }
```

> ⚠️ 该接口做严格字段校验：只接受上表字段，**不支持** `categorySlug`、`slug`、`tags`。传未声明字段会被忽略，但缺少 `categoryId` 会返回 `400 参数错误`。请以本节为准，旧版 `对外投稿接口.md` 中的字段描述已过时。

## 5. 更多调用示例

### Python

```python
import os
import requests

BASE = "https://www.luliming.xyz/XiaoBaiFinance"
headers = {"Authorization": f"Bearer {os.environ['OPEN_API_KEY']}"}

# 列表：分页遍历全部已发布文章
page = 1
while True:
    r = requests.get(
        f"{BASE}/api/open/v1/articles",
        params={"page": page, "size": 50},
        headers=headers,
        timeout=10,
    )
    r.raise_for_status()
    body = r.json()
    if body.get("code") != 0:
        raise RuntimeError(body.get("message"))

    for article in body["data"]["list"]:
        detail = requests.get(
            f"{BASE}/api/open/v1/articles/{article['id']}",
            headers=headers,
            timeout=10,
        ).json()
        print(article["title"], detail["data"]["article"]["contentText"][:80])

    if not body["data"]["hasMore"]:
        break
    page += 1
```

### JavaScript / Node.js

```js
const BASE = 'https://www.luliming.xyz/XiaoBaiFinance';
const headers = { Authorization: `Bearer ${process.env.OPEN_API_KEY}` };

const res = await fetch(`${BASE}/api/open/v1/articles?q=基金&size=5`, { headers });
const { code, message, data } = await res.json();
if (code !== 0) throw new Error(message);
console.log(`共 ${data.total} 篇`, data.list.map((a) => a.title));
```

## 6. 错误排查

| 现象 | 原因与处理 |
|---|---|
| `401` + `缺少 API Key` | 未带请求头，或用了 `?key=` 调数据接口（数据接口只认请求头） |
| `401` + `API Key 无效` | Key 复制不完整、已被删除 / 吊销；重新生成再试 |
| `400` + `参数校验失败` | `sort` 不是 `latest/hot`、`categoryId` 含非数字、`q` 超长等；看 `data` 里的字段明细 |
| `404` + `文章不存在或未发布` | 文章是草稿 / 已下架 / 已删除，或 `idOrSlug` 写错 |
| `429` + `调用过于频繁` | 超过每密钥每分钟配额，降低频率或分页批量拉取 |
| 浏览器控制台 CORS 报错 | 接口未开放浏览器跨域，请改为服务端调用 |
| 时间比北京时间少 8 小时 | 返回的是 UTC，展示时按 `Asia/Shanghai` 转换 |
